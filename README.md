# 🌌 Галактика — 3D AI Planner

Визуальный планировщик задач в виде интерактивной 3D-галактики с интегрированным ИИ-агентом. Задачи представлены как звёзды, планеты и другие космические объекты, связанные орбитами и гравитационными полями.

## ✨ Возможности

### Визуализация
- **3D-пространство** — бесконечная галактика с орбитальным управлением камерой
- **Иерархия объектов** — центр галактики, звёзды, планеты, спутники, астероиды, чёрные дыры
- **Неоновый стиль** — тёмная тема с яркими акцентами и эффектами свечения
- **Мини-карта** — быстрая навигация по всей галактике
- **Режим фокуса** — выделение выбранной задачи и её связей

### Управление задачами
- **Создание задач** — добавление новых объектов в галактику
- **Редактирование** — изменение названия, описания, типа, цвета, размера, тегов
- **Удаление** — удаление задач с автоматическим обновлением связей
- **Типы задач**:
  - 🌌 **Центр галактики** — корневая категория (Работа, Дом, Путешествие)
  - ⭐ **Звезда** — главный проект или цель
  - 🌟 **Кластер** — группа связанных проектов
  - 💫 **Система** — устойчивая совокупность задач
  - 🪐 **Планета** — крупная задача
  - 🛰️ **Спутник** — подзадача
  - ☄️ **Комета** — временная идея (с хвостом из частиц)
  - 🪨 **Астероид** — мелкая задача
  - 🕳️ **Чёрная дыра** — сложная/неразрешимая ситуация

### Связи между задачами
- **Иерархические связи** — родительские и дочерние задачи
- **Семантические связи** — произвольные связи между задачами
- **Режим соединения** — кнопка «Связь» для создания связей между задачами
- **Визуализация** — орбиты с эффектом свечения при выделении

### Источники и RAG-поиск
- **Привязка источников** — текстовые заметки, ссылки, документы
- **Изоляция источников** — источники привязаны к конкретным задачам
- **RAG с весами** — поиск учитывает расстояние от центра и связи:
  - Собственные источники (вес 1.0)
  - Источники от связанных задач (вес зависит от расстояния)
  - Источники от родительских задач (средний вес)

### ИИ-агент
- **Диалог с ИИ** — вопросы в контексте выбранной задачи
- **Быстрый ввод мысли** — модалка «💭 Новая мысль» с автоматическим ИИ-анализом
- **Интеллектуальная классификация** — ИИ определяет смысловой тип (идея, цель, задача, факт, проблема и др.), космический класс и стадию жизненного цикла
- **Панель «Входящие»** — предложенные ИИ связи и иерархии с кнопками «принять»/«отклонить»
- **Загрузка списка моделей** — получение доступных моделей из API провайдера (Ollama `/api/tags`, OpenAI `/v1/models`)
- **Реальная интеграция с Ollama API** — прямые вызовы к локальным LLM
- **Тестирование соединения** — кнопка для проверки подключения и автозагрузки моделей
- **Эвристический fallback** — анализ на основе правил при недоступности ИИ
- **Настройки API**:
  - Ollama (локальные модели) — `http://localhost:11434/api/chat`
  - OpenAI (GPT-4, GPT-3.5)
  - Custom endpoint
  - Demo режим (без API, эвристика)
- **Конфигурация только через UI** — endpoint и модель задаются в настройках, а не в `.env`
- **Контекстный анализ** — ИИ учитывает тип задачи, источники, связи
- **Обработка ошибок** — понятные сообщения при проблемах с подключением

### Управление
- **ЛКМ** — вращение камеры
- **СКМ (средняя кнопка)** — перемещение по карте
- **Колёсико** — зум
- **Клик по задаче** — выбор и просмотр деталей
- **Кнопка «Связь»** — режим соединения задач

## 🎮 Использование

### Создание галактики

1. **Центр галактики** — начните с создания корневой категории (например, "Работа", "Дом", "Учёба")
2. **Добавление задач** — кнопка "Звезда" создаёт новую задачу в случайном месте
3. **Настройка типов** — выберите тип объекта (звезда, планета, спутник и т.д.)
4. **Создание связей** — используйте кнопку "Связь" для соединения задач

### Работа с источниками

1. Выберите задачу
2. Перейдите на вкладку "Источники"
3. Добавьте текстовые заметки, ссылки или документы
4. Источники автоматически индексируются для RAG-поиска

### Диалог с ИИ

1. Выберите задачу
2. Перейдите на вкладку "ИИ"
3. Задайте вопрос или используйте быстрые команды:
   - "Предложи план декомпозиции"
   - "Выяви риски"
   - "Найди скрытые связи"
4. ИИ ответит с учётом контекста задачи и доступных источников

### Настройка ИИ API

1. Перейдите на вкладку "ИИ"
2. Нажмите ⚙️ для открытия настроек
3. Выберите провайдера:
   - **Demo** — работа без API (ограниченные ответы)
   - **OpenAI** — требуется API ключ
   - **Ollama** — локальные модели (укажите endpoint)
   - **Custom** — произвольный endpoint

#### Пример конфигурации OpenAI:
```
Провайдер: OpenAI
API Key: sk-...
Модель: gpt-3.5-turbo
```

#### Пример конфигурации Ollama:
```
Провайдер: Ollama
Endpoint: http://localhost:11434
Модель: llama2
```

**Важно:** Перед использованием Ollama убедитесь, что:
1. Ollama запущен локально (`ollama serve`)
2. Модель загружена (`ollama pull llama2`)
3. Используйте кнопку "🔌 Тест соединения" для проверки подключения

## 🔗 Связи и RAG

### Типы связей

- **Иерархические (hierarchy)** — родитель-ребёнок
- **Семантические (semantic)** — произвольные связи между задачами
- **Предложенные (suggested)** — связи, найденные ИИ-агентом

### RAG-поиск с весами

При запросе к ИИ учитываются источники из:

1. **Собственных источников задачи** (вес 1.0)
2. **Связанных задач** (вес = `1 / (1 + distance * 0.1)`)
   - Чем дальше задача от центра, тем меньше вес
   - Семантические связи имеют высокий приоритет
3. **Родительских задач** (вес = `0.5 / (1 + distance * 0.15)`)
   - Иерархические связи имеют средний приоритет

### Пример

Если задача "Дизайн UI" связана с "Разработка Галактики", то при запросе к "Дизайн UI" ИИ получит доступ к источникам из "Разработка Галактики" с высоким весом.

## 🐛 Известные ограничения

- RAG-поиск работает только с текстовыми источниками (`type: 'text'`)
- Нет поддержки файлов (PDF, DOCX) — только текст
- Нет экспорта/импорта данных (только localStorage)
- Панель «Входящие» показывает предложенные связи, но полноценная карточка разбора записи в разработке

## 🔧 Troubleshooting

### Ошибка подключения к Ollama

**Проблема:** "❌ Ошибка подключения к ИИ: Failed to fetch"

**Решение:**
1. Убедитесь, что Ollama запущен:
   ```bash
   ollama serve
   ```

2. Проверьте, что модель загружена:
   ```bash
   ollama pull llama2
   ollama list
   ```

3. Проверьте доступность API:
   ```bash
   curl http://localhost:11434/api/tags
   ```

4. Если Ollama запущен на другом порту, укажите правильный endpoint в настройках

### CORS ошибки

**Проблема:** Браузер блокирует запросы к Ollama

**Решение:** Ollama по умолчанию разрешает CORS для localhost. Если проблемы продолжаются, установите переменную окружения:
```bash
OLLAMA_ORIGINS=* ollama serve
```
